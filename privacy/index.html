Data handling

Privacy policy

Effective 15 October 2026 · SOIC Drive Sync

This policy describes the personal SOIC Drive Sync script and this informational website. The script is operated by its account owner for personal use. No public registration or shared mailbox service is offered.

Google information accessed

  • Gmail: The script requests Gmail read-only permission. Google grants this permission across the mailbox, but the application searches only SOIC announcement/session messages from its configured SOIC sender. It reads message headers and text bodies to extract dates, topics, and references. It does not send, modify, delete, label, or mark email as read, and does not download email attachments.
  • Google Drive: The script uses the owner’s Drive authorization to manage archive folders, content files, indexes, checkpoints and the membership tracker in the configured destination. The requested Drive permission is broader than one folder; the script’s configured behavior limits its writes to the selected archive.
  • Authorization credentials: OAuth client details and refresh tokens are used to obtain access tokens from Google. These credentials are not embedded in this public website or committed to the source repository.

How information is used

Gmail data is used to match session announcement dates and recording-notice dates with membership lessons. These dates are kept distinct from actual source upload dates. Ambiguous matches remain blank. Google Drive stores the resulting archive and tracker for the owner.

The sync does not sell Google user data, use it for advertising or profiling, or send it to an AI service or use it to train AI models. The script uses deterministic extraction and matching rules.

Storage and service providers

Google provides Gmail and Drive. GitHub Actions processes information when the hosted sync runs; its encrypted repository secrets hold the authorizations the owner supplies. Local runs store authorization and checkpoints on the owner’s device. The Drive checkpoint stores extracted dates, topics/subjects, message and thread identifiers, and matching references. Email bodies are processed in memory and are not persisted by the script; email attachments are not fetched.

Logs report progress counts and sanitized errors rather than credentials or email bodies. Archived membership files and tracker data remain in the owner’s Google Drive. Folder sharing is controlled by the owner; the application does not automatically make those files public.

Retention, deletion and revocation

Extracted records, archive files and local copies remain until the owner deletes them. To remove stored data, delete the relevant Drive archive/checkpoint and local report/checkpoint files. To stop future access, revoke the app’s authorization in Google Account connections and remove its GitHub secrets; disable the workflow to stop scheduled processing. Revoking authorization does not itself delete existing files.

Limited use

SOIC Drive Sync’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements. Google data is transferred only as needed to provide the owner-requested sync and storage features, or as required for security or applicable law.

This public website

This is a static information site. It has no account login, data-upload form, application analytics or tracking code of its own. No Gmail, membership content or OAuth credentials are sent to this website. The hosting provider may process ordinary technical request information under its own policies.

Questions and changes

For questions, use the support contact displayed on the app’s Google authorization screen. This page will be updated if the script’s data practices change.
